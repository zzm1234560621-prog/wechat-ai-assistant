# --- wcferry：**只有走 wcferry 后端（微信 3.9.x）才需要** ---------------------
# 项目主线是 **微信 4.x + aixed hook**（version.dll 注入，本地 HTTP :30001），
# 主线不需要 wcferry。装不上 wcferry **不影响主线**：
#   * installer 会明确报出「wcferry 没装上」，然后照常把其余依赖装完（不是静默失败）；
#   * 真要 wcferry 后端时，先把微信降到下表版本再装对应的 wcferry。
#
# 版本对应表（与 wechat_version.py 的 WX_TO_WCFER 保持一致，改一处要改两处）：
#   微信 3.9.12.51  -> wcferry==39.5.2
#   微信 3.9.12.17  -> wcferry==39.4.4
#   微信 3.9.11.25  -> wcferry==39.3.0
#   微信 3.9.10.27  -> wcferry==39.2.0
#   微信 3.9.10.19  -> wcferry==39.1.0
#
# 这里刻意**不写上界**：wcferry 的版本必须跟着微信版本走，写死一个版本会让
# 「微信 3.9.12.51 + 39.5.2」这类组合反而装不上。真正生效的版本由 installer.py
# 按检测结果覆盖（envsetup.set_version），手动安装时请照上面的表自己填 ==版本。
#
# ⚠️ 版本号写法：上面表里的 `39.5.2` / `39.4.4` 是「文档里的三位写法」，PyPI 上实际发布的
#    是四位版本（39.5.2.0 / 39.4.5.0 ……）。PEP 440 比较时 39.5.2 < 39.5.2.0，
#    所以这里写 `>=39.4.4` 会解析到 **39.4.5.0**，能装上但不是我们要的那个版本——
#    真要 wcferry 后端时，请用 installer.py 装（它会按微信版本覆盖成精确版本），
#    或自己 `pip install wcferry==39.5.2.0`。
wcferry>=39.4.4

# --- 运行时必需（和微信版本无关，主线同样需要）-------------------------------
anthropic>=0.40.0
setuptools<81
PyYAML>=6.0
# 读微信里收到的 PDF 用（find_files / read_file）。纯 Python、无编译依赖，
# 不和上面几家打架。docx/xlsx/pptx 不用库——都是 zip+xml，标准库就能扒。
pypdf>=4.0
# ⚠️ **zstandard 是核心依赖，不是可选项**（2026-10-06 第二台部署机真机）：
#    微信 4.x 把一部分 `Msg_` 的 `message_content` **用 zstd 压缩**存（长文本、appmsg、
#    **语音条的 XML** 都是）。`live_history.decode_msg_content()` 靠它解；缺了会**静默**
#    解成空串 —— 表现是「短消息一切正常，只有语音答不上来」：
#    `voice_info()` 拿不到 `voicelength` → 「拿不到这条语音的时长，认不出是哪一段」。
#    以前它只写在 .venv 里（手工装的，`pip show zstandard` 的 Required-by 是空的），
#    没进这份清单 ⇒ 换台电脑就缺 ⇒ 又是「开发机上好用、发布包里静默失效」那一类。
#    它很小（纯 wheel），把它写进这里，installer / 启动自检 / 一键部署 就都会带上。
zstandard>=0.22

# --- 可选：不随主程序安装 ----------------------------------------------------
# ⚠️ 这一段里的包**必须写成注释**，不许写成正式需求行。原因：`envsetup.requirements_specs()`
#    读的是**所有非注释行**，「可选」只是本文件里的约定，不是解析器认识的语法；
#    （`required_pkgs(backend)` 只按后端排除 wcferry 一个。）
#    一旦把可选包写成正式行，它会进 `required_import_names()` →
#    启动助手.bat 的自检清单会要求它 → 没装的人「装完还是起不来」死循环（H1 那一类），
#    installer 也会去装这个重包。下面 pywxdump 一直是注释，就是这个道理。
#
# faster-whisper：语音输入（把音频文件转成文字）用。用到时按提示单独装：
#     .venv\Scripts\python.exe -m pip install faster-whisper
# 装完还要下一次模型（显式执行 `python audio_read.py --setup`，绝不从聊天路径触发下载）。
# 走云端转写（audio.backend: cloud）则完全不需要它。见 docs/voice-input-spec.md。
#
# pywxdump 仅 export_history.py 手动导出时才需要；它强锁 protobuf==3.10.0，
# 与 wcferry 的 grpcio-tools 冲突会导致安装失败，故不随主程序安装。
# 需要手动导出时再单独装：pip install pywxdump
#
# Pillow：**只有 PDF 内嵌图片**这条支路才需要（pypdf 的 `page.images` 要它）。
# 不装也能读：扫描页绝大多数是 DCTDecode(JPEG)，file_read 会**自己从页里掏 JPEG 流**
# 直接喂系统 OCR（实测 564 页扫描件第 2 页走的就是这条路）。
# 装了它则多覆盖 FlateDecode 之类需要重编码的图。
#     .venv\Scripts\python.exe -m pip install Pillow
#
# av（PyAV，wheel 自带 FFmpeg）：**视频**读音频轨/抽帧用（P2）。不装则视频那一类读不了，
# 其余一切照常。它是这几个里最大的一个（几十 MB）。
#     .venv\Scripts\python.exe -m pip install av
#
# extract-msg：Outlook **.msg** 邮件最稳的读法。不装就退到 olefile（只取主题/正文/
# 收发件人，拿不到附件），再没有就如实说。
#     .venv\Scripts\python.exe -m pip install extract-msg
#
# py7zr（.7z 压缩包）/ rarfile（.rar 的**壳**）：
#     .venv\Scripts\python.exe -m pip install py7zr rarfile
# ⚠️ 只装 rarfile **不等于 .rar 能读**：真正解压靠**外部程序**（unrar / 7z / bsdtar）。
#     没有它时代码会如实说读不了——判据只有一份，在 `archive_read.find_rar_tool()`
#     （它连厂商默认安装位置一起找，所以「不在 PATH」不等于「没装」）。
#     本机实测（2026-10-05）：PATH 里没有，但 `C:\Program Files\7-Zip\7z.exe` **在**。
#
# xlrd：**老 .xls 表格**用它读（纯 Python，比启动 Excel 快也稳）。不装也能读——
# legacy_office 会自动落到 Office COM / WPS / LibreOffice 那一串。
#     .venv\Scripts\python.exe -m pip install xlrd
#
# olefile：老 .doc 的**最后一级兜底**（粗略抽取，质量不保证，会如实标注）。
# 不装就只有前四级；都没有就如实说读不了。.msg 邮件以后也会用它。
#     .venv\Scripts\python.exe -m pip install olefile
#
# sentence-transformers：**本地语义检索**（semantic_search 工具 / semantic.py）用。
# 不装则那个工具**如实报「没装依赖」并给出安装命令**，其余一切照常——
# 它**不会**退化成关键词搜索（那是明令禁止的，见 semantic.py 的模块注释）。
# 它还会拖进 torch，是这个清单里最重的一个，所以**绝不随主程序安装**；
# 「可选组件.bat」里它也是唯一**默认不装**（要手打 y）的一项。
#     .venv\Scripts\python.exe -m pip install sentence-transformers
# 装完还要显式下一次模型（**只此一条下载路径**，走 hf-mirror 镜像）：
#     .venv\Scripts\python.exe semantic.py --setup
# 再建索引（**要先把 bot 停掉**——遍历历史是重活，不能挂在轮询线程上）：
#     .venv\Scripts\python.exe semantic.py --build --days 90
# 只看状态 / 纯探针（给脚本和控制台用）：
#     .venv\Scripts\python.exe semantic.py --status
#     .venv\Scripts\python.exe semantic.py --ready      # 只回退出码，无输出
