## 资料优先级（从可信到不可信）

1. **本机源码快照**（最可信，就是线上跑的那份）：
   `installers/wechat-4.1.10.27/src-4.1.10.27/WeChat-Hook-4.1.10.27/`
   - 路由注册看 `http_routes.cpp`；各接口的请求/响应结构看对应的 `.h`。
   - **只有 5 组路由**：发文本 / 发图片 / 转发 XML / 解图片 / 查资料 / 查库。先读这里，很多问题直接就有答案。
2. **另一份快照**：作者发布包里解出来的那份（2026-06-24 版，放项目外任意目录；**别把个人绝对路径写进文档**）。
   **两份的 xLog hook 偏移不同，不要混用**；引用时要说明是哪一份。
3. **接口文档**：`showdoc.com.cn`，**密码统一 1234**。各版本的文档索引写在源码的 `README.md` 里。
   showdoc 需要密码、可能抓不到，抓不到就提醒用户密码是 1234，别反复重试。
4. **项目内 postman 集合**：`docs/aixed-api.postman.json`（8 个接口）。
5. **TG 群导出**：**已失效**（`messages.html` 里没有消息了）。**不要引用它**。要查群里的技术干货得让用户重新导出。

## 铁律

- **回答前先读源码。** 不要凭记忆答接口细节——偏移、字段名、路由都改过。
- **不确定就说不知道**，并指出该去哪个文件确认。宁可空手，不要编一个看起来合理的接口。
- **注意 hook 不支持并发**：文档里不会写这条，但它是真的（并发调用会把微信搞崩）。涉及"批量/并发调用"的需求要明确提醒。
- **有些能力根本没有**。已知：没有任何通话接口（`SendTextMsg` / 图片 / XML 之外没有语音视频通话），README 说明 main 分支移除了 PB 协议直发。被问到时直接说没有，别去文档里硬找。

## 报告要求

- 给出**文件路径 + 行号**作为依据，不要只给结论。
- 接口用法给一个能直接跑的最小示例（curl 或 python）。
- 明确标注不确定的部分。
