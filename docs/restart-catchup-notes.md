# 重启 / 换台电脑时，「哪些消息该被回答」（2026-10-06 定案）

## 事故三：换个电脑一登录，把所有问题又回了一遍（用户原话）

现场证据都在 `bot.log`（行号对应当天那份，已轮转）：

| 行 | 看到什么 |
|---|---|
| 881 | 它发了一条问候（本进程发的） |
| 884 / 887 | 它又**收到**一条同样开头的问候，措辞是另一套（「找文件、盯人都可以」），于是**又答了一遍** |
| 897 / 903 / 909 | 它**收到三条自己格式的**「🎤 收到一条语音，但没能读出来：拿不到这条语音的时长（XML 里没有 voicelength）」，逐条再答 —— 用户看到的就是那三条越来越长的语音解释 |
| 944 | 它收到自己上一轮的课表答复，把整个课表搜索**重做一遍** |

那三段被再答的文本，在 `bot.log` / `bot.log.1` / `data/bot_restart_out.log` 里**只有「收到」、没有「发出去」**：
它们不是这台机器现在的进程发的，而是**另一台电脑上那套助手**发的，随登录同步进了本机库。
`data/dialog.json` 是同一事实的另一面：「用户」那一侧的 turn 里躺着的就是助手自己以前的答复。

## 根因：两个判据都太窄

1. **「这条现在该不该处理」** 以前是「比 `state.stale_after`（120 秒）还旧 **且** 早于本进程启动」
   （`bot.py` 主循环）。于是**启动前 2 分钟内**产生的东西 —— 自己上一轮刚发出去的回复、
   换台电脑时同步进来的历史 —— 被当成**新消息照回**。
2. **「这句话是我刚发出去的」**以前只活在内存里（`_SENT_RECENT` / `is_own_reply`）。
   控制会话是文件传输助手、`respond_to_self: true`，助手自己发的字和用户打的字在库里**都是
   `from_self`** —— 这张表是**唯一**能区分「自己的回显」和「用户新提问」的东西；进程一重启
   它空了，于是自己答自己（早上的事故二是「认错了自己」，这是同一个症状的**另一半**）。

游标救不了场：它每 10 秒才落一次盘；而且换台电脑后微信会重建/同步索引，**rowid 语义对不上**
（同一天 `message_fts_v4_0` 从 `736` 跳到 `201488`）。`align_stale_cursors` 只救「游标跑到头部之外」，
救不了「历史被重新灌进本机库」。

## 修法

* `bot.is_catchup(msg_ts, start_ts, now)`（**判据本体，抽成纯函数是为了能自测**）：
  只剩「**早于本进程启动**」这一条。两个边界不许丢 ——
  * 时间戳取不到（`<= 0`）→ **不算补齐**（宁可多处理一条，也不许静默丢一条真·新消息）；
  * 时间戳落在未来（时钟被拨过）→ 也不算。
* `state.stale_after` 这个旋钮**退休**：两份 config 里那行删掉，改成一段解释。想「完全不续旧游标、
  只收启动后的新消息」用另一个旋钮 —— `state.resume_window: 0`（语义是启动时 `prime()`）。
* `_SENT_RECENT` **落盘**（`data/state.json` 的 `sent` 段，`load_sent_memory()` 启动时读回）：
  **只存 sha1 前 16 位指纹 + 时间戳，不存原文**（`state.json` 是会被翻开看的文件）；
  TTL 300 秒、上限 200 条。
* 回归：`selftest_bot_loop.py` 的 `t_catchup` / `t_sent_memory_durable`（含「配置文件里不许再有
  `stale_after` 键」和「主循环真的接了 `is_catchup`」两条钉子）。

## 用户可见的取舍（要说清）

**重启那几秒里进来的真消息，现在只通知、不自动回复**（会有一条「⚠️ 重启补齐：启动之前还有消息
没处理…」）。要它回答，重发一遍就行。这是用户 2026-10-06 明确要的：「不应该只回复登录之后的
新消息吗」。

## 别改回去的地方

* **别再把「消息年龄」加回判据。** 任何「启动前 N 秒内还算新」的宽限，都会把上一轮自己的回复
  当成新输入 —— 这正是事故三。
* **指纹不许换成原文**：落盘是为了扛重启，不是为了把回复内容留在 `state.json` 里。
* **TTL 不许放大。** 这条闸的代价是「对方恰好说了和我们上一条回复一样的话」会被静默丢掉；
  TTL 就是这个代价的上界。`selftest_bot_loop.t_own_echo_without_identity` 钉着「认得自己时不拦」。
* **无时间戳 / 未来时间戳不许改成「算补齐」**：那是拿静默丢新消息换干净日志。
