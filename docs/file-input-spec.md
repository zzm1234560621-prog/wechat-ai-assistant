# 任意文件与图片通读（read-anything）规格

> 状态：设计已与用户**逐条确认**（2026-10-02）。「二、已定决策」里那六条是用户拍过的，
> **不要再重新讨论**；要改先跟用户说。
> 前置规格：`docs/voice-input-spec.md`（音频已实现，本规格**复用**它，不重做）。
> 背景：`docs/wechat4-dat-image-notes.md`（别人发来的图是加密 `.dat`，本规格**不解决**那件事）。

## 一、目标与非目标

**目标**：微信里发来的**任何文件**——现代 Office、老 `.doc/.xls/.ppt`、PDF（含扫描页）、
压缩包、邮件、音频、**视频**、图片、以及一切纯文本——**本地全文解析（输入不设上限）**，
把**文字和图片**交给模型。用户说「读一下那份 xxx」就能拿到内容。

**非目标（明确不做，别顺手扩）**：

- ❌ **微信聊天里别人发来的图**（`msg/attach/**/Img/*.dat`）：前 1024 字节是 AES + 一把没拿到的
  固定密钥。本规格只保证「图能拿到字节的那些」（当文件发来的 / 自己发出去的 / 文档内嵌 / 视频抽帧）。
- ❌ **给别人发文件**：hook 只能发文本 / 图片 / 转发。
- ❌ **云端转换**（把私人文档传给第三方转换服务）：与本地优先立场冲突，永久不做。
- ❌ **把 GB 级文本整段塞给模型**：做不到也不该做，见「七、分页与导出」。
- ❌ 加密文档、带密码的压缩包、纯二进制/可执行文件的**内容**。

## 二、已定决策（2026-10-02 用户拍板，附依据）

| # | 决策 | 依据 |
|---|---|---|
| 1 | 输入**不限大小**，重活放**后台单线程**；解压后累计体积**保留绝对封顶** | 读文件现在同步跑在收消息线程上；拆掉炸弹防护＝几十 KB 的 docx 能解出几十 GB |
| 2 | 格式覆盖到**视频 / 邮件 / 压缩包** | 用户明确要 |
| 3 | 老格式走**多引擎降级**，不绑死 Office | 本机实测：Office COM 在、WPS/LibreOffice/antiword **都不在**；盘上 16 个老格式**全是真 OLE2** |
| 4 | 图片两路：`inline`（原图进当轮对话）/ `vision`（描述成文字），**配置切换** | 用户要"模型直接看图"；实测 `llm.py` 的 openai 通道**原样透传 content 数组** |
| 5 | 图片默认**免费 OCR 打底**，只在认不出字时才调视觉模型，**优先本机** | 用户问"有免费替代吗"；`image.mode: ocr` 本来就是默认，且离线无限额 |
| 6 | 聊天模型换 `deepseek-flash` | 已实测：收图（真 JPEG → 描述正确 + 读出图里的英文）、能调工具（24 个工具正常发出） |

## 三、架构：三层 + 一条后台线程

```
微信消息 → bot 主循环（收消息那条线程，**绝不阻塞**）
   read_file 工具
     ├─ 轻的（≤ file.inline_bytes 且不是重活）→ **同步**返回，行为同今天
     └─ 重的（大文件 / 老格式转换 / 视频 / 压缩包递归）→ 登记 job，立刻返回"已提交"
   ┌──────────────── read_worker（1 条线程 + 串行队列）────────────────┐
   │ 只做：读磁盘、解析、调模型（转写 / 描述）                          │
   │ 绝不做：查微信库、碰 hook、发消息                                  │
   └─────────────────────────┬───────────────────────────────────────┘
                             │ 结果进内存队列
   bot 主循环空档 drain → **由主线程发消息**（hook 只在主线程被碰）
```

**为什么 worker 不发送**：`hook 不支持并发` 是头号铁律。worker 只碰磁盘和模型 HTTP，
发送一律回主线程 —— 和 `scheduler` 挂在轮询空档里同一个姿势。

**排队要如实说**：同一时刻只跑一个读取任务。提交第二个时，回执里要写清
「前面还有 N 个在读，排队等着」；队列满（`read.queue_max`）就明确拒绝，**不静默丢任务**。

## 四、模块与责任

| 模块 | 职责 | 说明 |
|---|---|---|
| `file_read.py`（现有，**唯一入口** `extract()`） | 分派 + **内容嗅探**（魔数 + 可解码性）+ 分页/导出 | 不加新入口；工具签名几乎不动 |
| `archive_read.py`（新） | zip / 7z / rar 递归读成员，共享同一套解压预算 | 容器是独立机制；`file_read._zip_budget` 已有实现，搬过来复用 |
| `legacy_office.py`（新） | 老格式多引擎降级转换 | 唯一会**启动外部程序**的机制，必须能整体"不可用" |
| `video_read.py`（新） | 视频 → 音轨（交 `audio_read`）+ 关键帧（交 `image_read`） | PyAV，**不需要系统 ffmpeg** |
| `read_worker.py`（新） | 后台单线程 + job 生命周期（超时/失败/启动残留）+ 结果回传 | 第一次为读文件起线程，收在一个文件里才好测 |
| `image_read.py` | 新增 `inline` 交付 + `ocr_first` 链 + 描述缓存 + 降采样 | |
| `agent_tools.py` | `read_file` 加 `cursor` + 重活转后台分支 | |
| `bot.py` | 主循环 drain worker 结果 + 读完汇报（同 `scheduler action=ask`） | |
| `llm.py` | **openai 通道不用改**（实测透传）；anthropic 通道要加图片块翻译 | |

## 五、硬约束（不可谈）

1. **worker 绝不查微信库、绝不碰 hook、绝不发消息。** 回归用例用 `_Boom` 客户端断言
   「读文件这条路径零次 `query_sql`」。
2. **解压炸弹的封顶不可关闭**。`file.max_unpack`（默认 200MB）卡的是**解压后累计**体积：
   输入文件本身不限大小，但一个 50KB 的包想解出 10GB 一定被拦。
3. **图片只进当轮，绝不进 `bot.dialog_*`**。`dialog_append` 会 `str(content)`（数组进去＝垃圾），
   而且那份记忆**每轮重发**，图进去＝反复计费。
4. **失败一律如实 + 可照做**：缺依赖 / 缺模型 / 超时 / 加密 / 读不出字 —— 每种一句能照做的话，
   **绝不用空字符串假装成功**，绝不静默降级到别的后端。
5. **老格式转换必须「只读 + 无窗口 + 带超时」**，超时强杀并留日志；**绝不允许改用户文档**。
6. **可选依赖一律写成 `requirements.txt` 的注释**（`faster-whisper` 那次「装完还是起不来」
   死循环的教训）；缺哪个只影响那一类能力，其它一切照常。

## 六、配置（新增/变更）

```yaml
file:
  max_bytes: 0            # 0 = 不限（本地解析都能读）；解压后另有封顶
                          # ⚠️ 实现必须**显式判 0**：现有代码是 `int(v or 30MB)` 的写法，
                          #    0 是 falsy 会被当成"没配"退回 30MB —— 那就静默违背了这条决策
  max_chars: 20000        # 一次交给模型的字数上限（多了走分页 + 导出）
  max_unpack: 209715200   # 解压后累计 200MB 封顶（防炸弹，别关）
  inline_bytes: 2097152   # 超过它就走后台 worker（默认 2MB）
  job_timeout: 1800       # 单次读任务超时（秒），超了如实说
  export_dir: "./data/exports"

read:                     # 后台读取队列
  queue_max: 5            # 排队上限；满了如实说"前面排满了"，不静默丢

image:
  mode: ocr               # off | ocr（默认，免费离线）| vision（描述成文字）| inline（原图进当轮对话）
  ocr_first: true         # mode=vision/inline 时也先跑 OCR：挑出足够的字就不调视觉模型
  ocr_min_chars: 20       # 「够多」的判据
  max_bytes: 5242880      # 聊天缩略图那条 OCR 路的上限（**不动**）
  send_max_bytes: 8388608 # 任何图**送模型**（inline/vision）的上限
  downscale: 1024         # 送模型前长边压到多少（0 = 不压）——图片 token 随分辨率涨
  max_per_round: 3        # 一轮最多送几张图（费用闸）
  cache_file: "./data/vision_cache.json"   # 按图片 md5 缓存描述：同一张看两次不重复计费

legacy:                   # 老 .doc / .xls / .ppt
  engines: auto           # auto = 按下述顺序挑第一个可用的
  # Office COM → WPS COM → LibreOffice headless → antiword（仅 .doc）→ olefile 粗略抽取
  office_timeout: 120     # 单个文件转换超时（秒）

video:
  max_seconds: 1800       # 单次取前 30 分钟音轨（**是节选就要说出来**）
  # 更长的视频不设总上限：结果里带 cursor（已转到的秒数），用户说「继续」就转下一段
  frames: 4               # 抽几帧交给图片通道
  frame_max_pixels: 1024

archive:
  max_depth: 2            # 压缩包递归层数
  max_members: 100        # 单个包最多读几个成员
```

## 七、分页与导出

- 提取出的**全文**写到 `file.export_dir/<sha1(名字+大小+mtime)>.txt`，返回里给
  「前 `max_chars` 字 + `cursor`」。
- 用户/模型说「继续」→ `read_file` 带 `cursor` 读下一页，**不重不漏**（用例钉住）。
- **同一套 cursor 也用于长音视频**：`video.max_seconds` 卡的是**单次一段**（默认 30 分钟），
  更长的给"已转到第 N 秒"的 cursor，说「继续」转下一段 —— 所以**总时长不设上限**，
  代价是"一次只给一段"，这一点要在结果里说清楚。
- 导出文件是临时物：超期或超过 50 份时清最老的，**清理要打日志**（静默丢弃不允许）。

> **音频上限一并放宽到 1800**（`audio.max_seconds`）。理由：`voice-input-spec.md` 里那条
> 120 秒上限的**原始理由是「跑在轮询线程上、不能长时间占着」**；重活改走后台 worker 之后
> 那个理由不成立了，所以音视频用同一个数。想严格可以单独把 `audio.max_seconds` 调小。
> 代价照实说：本机 CPU 转写 30 分钟音频要等几分钟到几十分钟，期间别的读取任务排队。

## 八、图片交付：四模式 + 免费优先链

```
任何一张图（当文件发来的 / 自己发的 / Office·PDF·压缩包内嵌 / 视频抽帧）
 ├─ 先跑系统 OCR（免费、离线、无限额）
 ├─ 抽出 ≥ ocr_min_chars 个字 → 判定「有字的图」→ 用 OCR 结果，**一次视觉模型都不调**
 └─ OCR 几乎为空 → 才调视觉模型
        优先级：本机 Ollama(http://localhost:11434) → 云端（含免费档）→ 如实说"看不懂画面"
```

- `ocr`（默认）只走第一段；`vision` 走完整链；`inline` 把**原图**按当轮消息内容塞进 `messages`。
- **`inline` 要求当前聊天模型支持视觉**（如 `deepseek-flash`）。模型不收图时**必须如实说**
  「当前模型不收图，请在 config.yaml 把 model 换成支持视觉的，或把 image.mode 改成 vision」——
  绝不允许悄悄退回只有文字、让用户以为模型"看过图了"。
- 送之前按 `image.downscale` 压、按 md5 查缓存。
- 实测报文形状（已验证可用）：
  `{"role":"user","content":[{"type":"text",...},{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,…"}}]}`

## 九、格式矩阵与失败语义

| 类别 | 支持 | 用什么 | 拿不到时怎么说 |
|---|---|---|---|
| 纯文本/结构化 | ✅ 任意后缀**按内容嗅探** | 魔数 + 解码（BOM→utf-8→gb18030→big5） | 「这看起来是二进制，不是文本」 |
| 现代 Office | ✅ **含里面的图片** | zip + XML（现有）+ `word|ppt|xl/media/*` | 内嵌图抽不出时说明是哪一种 |
| 老 Office | ✅ | `legacy_office` 降级链 | 逐级说「缺哪个引擎、怎么装」，最后如实说读不了 |
| PDF | ✅ 含**扫描页/内嵌图** | pypdf + 页图 → 图片通道 | 抽不出字时明说「是扫描件」 |
| 音频 | ✅（已实现） | `audio_read` | 见 `voice-input-spec.md` |
| 视频 | ✅ | PyAV 抽音轨 + 抽帧 | 缺 `av` → 「pip install av，或直接发音频/截图」 |
| 压缩包 | ✅ zip / 7z；rar 需外部解压器 | `archive_read` | 逐条说清哪个成员读不了、为什么 |
| 邮件 | ✅ `.eml`（附件递归）；`.msg` 需 `extract-msg` | 标准库 / 可选库 | 缺库 → 怎么装 |
| 数据库 | ✅ `.sqlite/.db` 只读列表 + 限量行 | stdlib `sqlite3` | 表太大 → 只给前 N 行并说明 |
| 微信 `.dat` 图 | ❌ | — | 「别人发来的图是加密的，我拿不到字节」 |

## 十、工具契约变化（**改了要两处一起改**）

- `read_file` 新增可选参数 `cursor`（续读下一页）。
- 重活分支返回：「**已提交后台读取**（文件名），读完我会主动发消息；**现在你还没有内容，
  绝对不要编造**。」（同 `run_command` 的「没跑就是没跑」）
- 读完后由主线程发一条汇报（可让模型总结一遍），同 `scheduler action=ask` 的姿势。
- `agent_tools.TOOLS` 与 `config.yaml` 的 `system_prompt` **必须同步改**（项目规矩）。

## 十四、风险与对策

**要你自己复核的（机器验不了的那几条）**：

1. **音轨/音频的“真人说话”转写**：本机没下 faster-whisper 模型（规格定了模型只由你显式下）。
   跑 `.venv\Scripts\python.exe audio_read.py --setup`，然后把一个**有说话声的视频/音频**

3. **`.rar`**：要装 `rarfile` **加**一个外部解压器（unrar/bsdtar）；没有就只能如实说读不了。
4. **视频画面走视觉模型**（`image.mode=vision`/`inline`）：需要配视觉模型的 key；
   默认的 OCR 那条已经真机验过。
