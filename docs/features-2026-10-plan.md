## 目标与验收

| # | 功能 | 验收标准（可观察） |
|---|---|---|
| 1 | `/自检` | 在微信里发 `/自检`，回一段人话诊断：hook 通不通、登录掉没掉、fts 句柄、游标停没停、慢查询、发送失败累计。**跑在 bot 内、用已收集的事实**，不许为此新增查询路径 |
| 2 | watch 关键词/正则 | `/盯着 关键词 <正则>` 之后，**任意会话**出现该词就通知我；非法正则当场报错；复杂度过高的正则要拒绝（防回溯爆炸卡住轮询） |
| 3 | 看护诊断 + 自愈汇报 | 连续 N 轮游标不动 → 自动 `force_rescan` → 若无效，在控制会话**主动**回一条「我怀疑 X，已试过 Y，需要你做什么」 |

| 8 | 发送指纹持久化 | 已发送指纹落 `data/state.json`，重启后**不重发**；窗口过期要说清 |

## 硬约束（任何一项都不许破）

1. **hook 不支持并发**（已崩微信 6 次）→ 新功能不许新增并发查询。重活只能进 `read_worker` 那条线程（它被明令不碰 hook）。
2. **`health` / `status_page` 绝不查库、绝不起线程碰 hook** → `/自检` 复用已收集的事实，不新增查询。
3. **不可逆动作必须确认**；**发送失败只告警不重试**。
4. **不许静默降级 / 静默失效**：做不到、没做、被截断、认不出，一律如实说。
5. **新增 agent 工具要改三处**：`agent_tools.TOOLS` + `config.example.yaml` 的 system_prompt + 本机 `config.yaml`。`selftest_tool_registry.py` 守着。
6. **新增顶层配置段必须同时进 `config.example.yaml`**（同一个闸门守着）。
7. **会让本机数据出网的功能默认关**（语义检索只能用本地模型）。
8. **`live_history.py` 是唯一读微信库的地方**；新增查询加在那里并复用它的缓存。

## 任务（按依赖与风险排序）

### T1 · 发送指纹持久化（#8）
- **文件**：`bot.py`（`remember_sent` / `is_own_reply` / `remember_sent_image` / `is_own_image`）
- **改法**：内存表之外落一份到 `data/state.json`（`sent_fingerprints`），载入时恢复；写入沿用 `_state_save()` 的原子写。
- **兼容**：窗口语义不变（默认 300s / 30s），过期项清理。
- **验证**：新增用例——写入 → 模拟重启（清内存、重新载入）→ 仍认得出；过期后不认。
- **回归风险**：误判会**丢掉对方真发的图**（现有注释专门警告过），所以宁可漏判：取不到时间戳时不落指纹。

### T2 · `/预算`（#5）
- **文件**：`usage.py`（新增 `budget_status` / `over_budget`）、`bot.py`（命令 + 调用前闸门）、两份 config
- **改法**：`budget.daily_cost`（0 = 不限）。`llm` 调用前查当日累计；超限就**拒绝调用**并回复明确原因与当前数字。
- **验证**：用例覆盖「未超限放行 / 超限拒绝 / 0=不限 / 没有价目表的模型怎么算」。

### T3 · `/自检`（#1）
- **文件**：`bot.py`（新命令 + 组装函数）、`health.py`（若缺字段则补）
- **改法**：纯组装 `Health.snapshot()` + `live_history.poll_errors()` + 游标 + 登录态；**不新增查询**。复用 `_probe_login`（已有）。
- **验证**：用例喂一个假的 snapshot/poll_errors，断言输出里**每个异常都出现**、且正常时说明「一切正常」。

### T4 · 看护诊断 + 自愈汇报（#3）
- **文件**：`health.py`（游标停滞判定）、`bot.py`（主循环里触发一次 `force_rescan` 并汇报）
- **改法**：连续 N 轮游标不动 → 记一笔诊断 → 调一次 `live_history.force_rescan`（自带 45s 限流）→ 成功就汇报「已自愈」，失败就汇报「需要你扫码/看日志」。
- **验证**：用例覆盖「不动 N 轮触发一次 / 恢复后不再触发 / 限流内不重复」。

### T5 · watch 关键词（#2）
- **文件**：`watch.py`（记录 `{kind: chat|keyword, pattern}`）、`bot.py`（主循环里对每条消息做匹配）、两份 config
- **改法**：`/盯着 关键词 <正则>`；正则编译失败当场报错；**限制**：长度上限 + 拒绝嵌套量词这类高危模式（防回溯）。
- **验证**：用例覆盖「命中就通知 / 不命中不通知 / 非法正则报错 / 高危正则被拒」。

### T6 · 导出对话（#6）
- **文件**：`live_history.py`（分页取全部历史）、`bot.py`（`/导出` 命令）
- **改法**：分页拉取 → 渲染成可读 md → 落 `data/exports/`（复用 `file.export_dir` 的清理）；落了盘给路径；超过上限如实说「只导了前 N 条」。
- **验证**：用例覆盖「导出成功且文件内容含双方发言 / 超限如实说 / 空会话如实说」。

### T7 · 语音条 `--probe`（#7）
- **文件**：`voice_msg.py`
- **改法**：记录一次基线快照 → 用户播一条语音 → 再扫，找新增/变化的候选文件，按 `length` 比对，对每个候选跑多方案解密，**用魔数（`#!SILK_V3` / `#!AMR` / `RIFF`）判定**；都不中就如实说「没找到/没解开」并列出试过什么。
- **验证**：用例用假文件目录 + 假魔数覆盖「找到并判定 / 没找到如实说 / 解不开如实说」。

### T8 · 多账号（#9）
- **文件**：`bot.py`（`--account`、锁端口、`STATE_PATH`、导出/缓存目录）、`envsetup.py`（按账号分区）、两份 config
- **改法**：`account.id`（默认空 = 现有行为，路径与锁端口完全不变）。指定后：state 文件变 `data/state-<id>.json`、锁端口偏移、导出行加账号名。
- **验证**：用例覆盖「不指定账号 → 路径与现在逐字节一致（兼容性硬断言）/ 指定账号 → 路径含账号名 / 两个账号的锁端口不同」。
- **风险**：这是本批唯一碰「启动路径」的改动，兼容性断言是它的护栏。

### T9 · 本地语义检索（#4）
- **文件**：`semantic.py`（新）、`agent_tools.py`（`search_history` 加 `mode=semantic`）、`live_history.py`（批量取文本）、`audio_read.py` 式的 `--setup`
- **改法**：本地 embedding 模型（`--setup` 显式下载，走 hf-mirror）+ 向量索引落 `data/semantic/`；查询时**只在索引存在时**走语义；索引不存在 → 明说「语义索引没建，跑 `python semantic.py --setup`」，**绝不静默退回关键词**。
- **验证**：用例注入**假 embedder**（项目既有约定：`fetcher` / `_Boom` 都是这么注入的）覆盖「索引缺失如实说 / 建好能检索 / 增量更新」。**真模型不在自测里跑**（不许自测下载模型）。
- **未覆盖**：真实模型的检索质量需要用户跑一次 `--setup` 才能验；这一点必须在文档与最终报告里说清。

## 风险与保留决定

- **#9 多账号**：不做「同时跑两个账号共享一个 bot 进程」——那会让两路查询压在同一个 hook 上（崩溃的原始死因）。做法是**一个账号一个进程**。
- **#4 语义检索**：绝不用云端 embedding（等于把整条聊天记录送出本机，和 `search.enabled` 默认关的理由直接冲突）。
- **保留的旧路径**：`verify_real.py` 保留（「bot 停着」时的体检工具），`/自检` 是「bot 跑着」时的对应物；两份工具的分工写进文档，不合并。
